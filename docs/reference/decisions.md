# Decisions

What the engine holds to, what it refuses, and what has been settled and why, so
nobody spends a day re-proposing something settled and nobody mistakes a
measurement for a law.

It is built to be **finished rather than rewritten**. Success is whether it still
holds up in three years without a subsystem being torn out, not how many features
ship this year. Every trade below follows from that.

## What must stay true

Breaking one of these is a design problem to raise, not a tradeoff to make.

- **Engine code never names a graphics API.** The GPU is reached only through
  abstract interfaces - `RenderBackend` for the frame, `EditorRenderHooks` for
  authoring-only work, vkmPlatform's `WindowSurface` for the window it draws into
  ([architecture.md](architecture.md#what-everything-else-stands-on)). No file outside
  a backend's places - `src/backend/<api>/`, `shaders/<api>/`, `tests/**/<api>/` and the
  hosts' one choice, `app/backend_choice.h` - names a graphics API, its library or a
  backend class, comments included, in `src/`, `app/`, `tests/`, `examples/` or
  `templates/`; the docs suite holds it.
- **Engine code names no OS or window API.** The Windows headers and GLFW are vkmPlatform's, and
  Winsock is vkmNetwork's: what the engine asks of the system - a window and its input, threads, a
  child process, a library loaded, where a user's files go, a stop asked for - it asks through
  them. The OpenGL backend (its window surface and ImGui's renderer) and the editor reach GLFW
  through `vkm_platform/glfw_api.h`, linking `glfw` themselves; nothing a game can include
  reaches it.
- **`Scene` is never edited to "support" a component.** Any plain struct is a
  component already; `scene.add<T>(entity, ...)` is the whole mechanism.
- **Components hold `Handle<T>`, never asset pointers or copies.** Serialization
  stores asset *names*, resolved back to handles on load. `UIText` names its font
  instead: a font is baked by the host, not loaded with a scene ([ui.md](ui.md#fonts)).
- **Systems never call each other.** `FrameContext` is the only per-frame channel
  between them. `EditorSystem` is the one sanctioned exception and is not a
  precedent ([architecture.md](architecture.md#what-everything-else-stands-on)).
- **A serialized or cooked format never grows a back-compatibility read path.** No
  migration step, no `if (version == 1)` branch, no two live readers. What each
  format's version gate does with an old file differs
  ([io.md](io.md#what-each-formats-version-gate-does)).
- **Windows and Linux only.** No macOS branches, no macOS in the docs.
- **A library's debug features follow flags.** Each library in `modules/` has a flag per debug
  feature it has (`VKM_<NAME>_ASSERTS`, `VKM_<NAME>_PROFILER`, ...), off by default and never
  keyed on `NDEBUG`; the engine sets each from its own (`VKM_ASSERTS`, `VKM_PROFILER`), so a dev
  build's libraries assert where the engine does and a shipping build's do not. One follows the
  build type instead: vkmOpenGL's read of GL's error queue after every call
  (`VKM_OPENGL_CHECKS`) is on in a Debug build alone, under a multi-config generator too, as each
  read is a round trip to the driver.
- **A position is reopened with the owner; a measurement, by measuring.** All of
  this section, [what the engine refuses](#what-the-engine-refuses) and the rows of
  [the table](#what-has-been-decided) marked *Position* are the owner's, and arguing
  one inside a task is out of bounds. Every other row of the table is a measurement
  ([below](#what-has-been-decided)), and a result that overturns one goes to the owner.

## What the engine refuses

Positions, not preferences, each with its reason:

- **No back-compatibility for old formats.** A migration path is permanent weight
  for a transitional problem, and two live formats mean every reader must know
  both. The cost lands elsewhere: a format has to be right the first time, so
  scrutinize a format change harder than almost anything else.
- **No temporal antialiasing, ever.** Not "not yet". Techniques that need a temporal
  filter are off the table with it.
- **No speculative abstraction.** No flag, virtual or interface without a concrete
  second user you can name today.
- **No engine-level render pass abstraction.** Passes are a backend detail. The
  engine's view of rendering is `RenderBackend`, the backend-agnostic `RenderView`
  it is handed, `EditorRenderHooks`, and the `WindowSurface` the window presents
  through. No fifth without the owner.
- **No bulk recovery of pre-refactor code.** A rewritten subsystem is not mined for
  the missing feature; it is written fresh against the new shape. Recovered code
  carries the assumptions of the design it came from.

## Changing a shape its users rely on

The engine is designed for itself: a shape is right because of what the engine is,
never because of who uses it. A game's need is a requirement the engine meets with a
feature of its own; once met, the game uses that feature and keeps no copy of it. A
second way kept for a game, an example or an old file is two designs, and the engine
pays for both. So a change of shape carries its users with it, in one pass:

1. **Change the engine** to the shape it should have. Delete the old one; keep no
   alias, overload, fallback or second spelling for anyone.
2. **Find every user**: `src/`, `app/`, `tests/`, `templates/`, `examples/`,
   `content/` and the docs - their code and their saved scenes, prefabs and recipes.
3. **Port each one.** Code moves to the new shape. A saved file is re-saved in the new
   format, by the editor or a one-off script that is not committed; the engine gains
   no reader for the old one.
4. **Build and run each project** you touched.

## What has been decided

A row is one of two kinds:

- **A position** - the owner's choice of what the engine is. It is marked so, and no
  number moves it.
- **A measurement** - what was built or tried, and why it was kept or dropped. It
  holds where it was taken, on the machines and scenes its commit names. A
  measurement says what reopens it - other hardware, a larger scene, a second
  backend, a cost showing in a capture - and one that does not is unfinished, not
  final. A row keeps the number that decided it; the rest are in its commit.

| Decided | Outcome and reason |
|---|---|
| The engine and its users | *Position.* The engine is designed for itself: nothing stays because a game, an example or an old file uses it, and a better shape replaces the old one with its users ported ([above](#changing-a-shape-its-users-rely-on)). |
| Temporal AA | *Position.* Rejected permanently. AA is MSAA plus `specularAA()` in the forward shader. |
| Screen-space shadows | *Position.* Removed. Shadows come from the shadow maps and, for fixed lights, the lightmaps ([lighting.md](lighting.md#baked-shadows)). A contact shadow marched through the depth buffer sees only what the screen holds: it guesses each surface's thickness, and breaks up at the screen's edges and behind whatever hides a caster. Revisit only with a shadow that sees past the screen, such as a ray-traced one. |
| Screen-space reflections | Adopted for near-mirrors alone, without a temporal filter: on water and polished floors probes cannot show what moves or what lies between them, while a rougher material's blur leaves a trace little to add over the parallax-corrected probes. The material's own roughness decides (`GLReflectionPass::MAX_ROUGHNESS`), not what a pixel's distance or ripples add, so a far sea stays a mirror. Coherent rays and a neighbor-averaged resolve stand in for TAA ([lighting.md](lighting.md#where-the-ambient-comes-from)). Revisit if a project's glossy surfaces show the trace's noise, its cost shows in a capture, or a rougher material visibly misses what moves before it. |
| Planar reflections | *Position.* Not in the engine. Reflections are the screen-space trace and the probes: each mirror would be a second drawing of the scene, for a third mechanism beside those two. A mirror that must show what is behind the eye is a missing feature, added when a project asks. |
| What the reflection trace costs a frame | Level 0 of what a hit reads is the lit scene itself, not a full-size copy of it, and the chain starts at half size; a ray takes `MAX_STEPS` at most and `REFINE` of bisection (`shaders/opengl/light/reflection/trace/fragment.shader`), as more changed nothing in the bench's views. A pixel that traces nothing still costs the fetch that says so: a view with almost no glossy pixels still pays a good share of a trace. Which materials can trace is not known ahead, as a roughness map can take any material under `MAX_ROUGHNESS`, so no object test can skip it short of a stat on each map; not built. Revisit if thin geometry goes missing from a mirror. |
| A hierarchical (Hi-Z) walk for the reflection trace | Built, measured, reverted. It found thin geometry the march skips, but its pyramid cost CPU every frame and an ordinary scene paid more GPU with nothing different to see. Revisit when a project's glossy surfaces visibly lose thin geometry. |
| Cone specular occlusion from GTAO's bent normal (GTSO) | Built, measured, reverted. It counts the part of a glossy floor's lobe that lands on the floor as black, visibly darkening the floor's reflection of the horizon. Lagarde's AO-only fit stays. Revisit with a specular occlusion that reflects the occluder's radiance rather than black. |
| GTAO and fog at a rate cap | Adopted while the eye holds still: each is worked out at most `GLRateCap::MAX_RATE` times a second, and the frames between read the last one's; a frame whose eye moved works both out again. No history is blended, so nothing smears. It buys nothing below that frame rate, and half of each at twice it. Under a turning eye the last one's occlusion lagged every edge, so a moving eye pays the whole cost. Revisit with a reprojection that keeps the last one's under a turn. |
| Visibility-bitmask GTAO (Therrien et al. 2023) | Built, measured, reverted. Its assumed thickness made a thin pole occlude as a slab, and the halo it exists to fix was already small. Revisit with a thickness taken from the scene rather than assumed. |
| SDFGI / voxel GI | *Position.* Never built, not planned. Indirect diffuse is a baked SH-L1 irradiance volume and reflection probes, occluded by GTAO and, on fixed surfaces, by the sky their lightmaps see. |
| Auto-exposure | *Position.* An option, off by default (`autoExposure`): a game moving between dark interiors and daylight needs it, one lit alike keeps its authored exposure, and the look stays the project's choice. Measured on the GPU, read back without a stall, decided on the CPU (`system/render/exposure.h`), so another backend adapts alike. |
| Shadow bias units | Texels of the map at the receiver, for every light (Castano 2013): one pair holds for any range, cascade or distance. `Light::SHADOW_BIAS` and `SHADOW_NORMAL_BIAS` leave no acne and keep a thin caster's shadow on a wall just behind it. Revisit if a light type or range needs a pair of its own. |
| Shadow atlas tile sizes | A held layer is `shadowResolution` across, a cascade each, in a texture of their own; the atlas's largest tile is half that. What moves under the sun takes the largest, a tile a cascade, a quarter of a layer's texels: its three-texel filter spans what six of the layer's would, so a mover's edge is a little softer than a fixed caster's, and its tile costs a quarter to clear and keep. A spot's tile follows how much of the screen its cone covers, up to half a layer. Revisit with another cascade count, or a spot that fills the screen and shows its texels. |
| Culling shadow casters by size | Adopted: a caster whose box spans fewer than `MIN_CASTER_TEXELS` texels of a tile or cube face is not drawn into it ([lighting.md](lighting.md#shadow-atlas)). Its shadow there is a few texels the filter blurs into a smudge, and a thin wire's drawn a texel wide is wider than the wire. It saves most where texels are widest, in the lower tiers' maps. Revisit if a small caster's shadow is seen fading out where a cascade hands over. |
| Baked shadows for fixed lights | Adopted: a light with `movable` off has the shadows fixed meshes cast in it baked into lightmaps ([lighting.md](lighting.md#baked-shadows)). The shadows were baked first, not the light: they were most of a fixed light's cost per pixel, and the live light keeps its specular. A fixed light that moves is drawn live while it moves, and once it holds still bakes its own channel alone over a copy of the rest, in a few seconds of play without a hitch: the whole re-bake outlasted the pauses of a sun stepped in play and never landed, and a sun turning from load held the loading screen to its limit with nothing baked. Revisit with indirect light in the lightmaps. |
| Baked sky occlusion | Adopted: every fixed surface's lightmap holds the share of the sky it sees past the fixed meshes, baked as suns spread over the dome through the shadow bake's own maps ([lighting.md](lighting.md#baked-shadows)), and the forward pass takes the strongest of it, GTAO and the material's AO. GTAO still gives what moves and what is finer than a texel; the bake gives what lies off screen or beyond GTAO's reach, at every tier, Performance's and Low's too, where GTAO is off. It is the sky's share, not light: maps drawn from outside cannot see into a room, so under a reflection probe it takes off only the sky the probe's center sees and the texel does not, and inside the irradiance volume, whose grid holds what its box shuts out, it gives way. Revisit with bounce light in the lightmaps, or a ray query that sees indoors. |
| Soft shadows by a blocker search (PCSS) | Replaced by a fixed filter: Castano's PCF, three texels wide for every light ("Every live shadow by the hard filter", [lighting.md](lighting.md#shadow-atlas)). The search and the wide disk it sized were most of the forward pass's cost per pixel, for penumbrae that widen with a caster's height; the fixed filter keeps the edge soft and clean without them. Settling the search from each shadow-map square's nearest depth had been built and reverted: the points it ran for were mostly casters too. Revisit if a project's tall casters need live penumbrae that widen with height. |
| ACES's 1/0.6 pre-scale | Dropped. Applied, it visibly lifts every scene authored here, and the examples read washed out. Revisit with scenes authored against the reference ACES transform. |
| How many tonemaps | *Position.* Two: ACES for contrast, Hable for a softer look. Reinhard, Khronos PBR Neutral and AgX each cost a branch in the composite for a look a grade can reach. |
| Color grading | Adopted: a 3D table authored as a strip image (`RenderSettings::gradingLut`), applied after the tonemap to display values - the frame as a screenshot holds it - before the dither, so an artist grades a screenshot and the neutral strip together in any image editor ([rendering.md](rendering.md#color-grading)). A table over the HDR frame, before the tonemap, would need its input in a log encoding no image editor shows. Revisit if a grade must reach detail the tonemap has already pressed into white. |
| Depth of field | *Position.* Not in the engine. No game asked for it: the one use was a stress load. A lens effect is a missing feature, added when a project asks. |
| The sky's brightness | Lit by the scene's sun (`Atmosphere::solarIlluminance`), with no constant: `lightIntensity` is an illuminance and the bake's scattering is per steradian, so the units agree; a separate sun intensity put far too much of the light in the sky. Tune haze as `mie`, not as a constant. Revisit if a project's sky and sun disagree in a way haze cannot tune. |
| The sky's ground albedo | `Atmosphere::GROUND_ALBEDO`, Hillaire's value: the ground past a scene's floors reads as they do. Darker grounds left a dark band, or a void, below the horizon. Revisit for a world whose ground is far darker or brighter than its floors - an ocean, snow. |
| The sky drawn from a sky-view table | Adopted, Hillaire's: the skybox reads a table computed every frame rather than the baked env cube, so the sky drawn is always the current sun's and the horizon is not a cube texel. Revisit if the table's cost shows in a capture. |
| The sky's lighting baked a step a frame | Adopted: baked whole, the env cube and its convolutions drop a frame each time a moving sun needs them. The price is a second set of cubes and ambient light trailing a moving sun by a bake or so; a sun run ahead of the shown sky takes more steps a frame, up to `GLIBLBaker::MAX_CATCH_UP_STEPS`, so its light keeps pace ([lighting.md](lighting.md)). Revisit if the trailing ambient shows under a project's moving sun. |
| Importance-sampled sky convolutions | Adopted (Colbert and Krivanek 2007): each convolution draws its samples by its own lobe and reads the env level its share of the lobe covers, at a fraction of the brute-force bake's cost. The render suite holds them to skies with an answer in closed form. Revisit if an HDR sky's convolution shows the sampling's noise. |
| A smaller env cube for the procedural sky | Not adopted. A smaller cube saved little of the bake, and a mirror would lose the horizon's edge. Revisit if the env cube's share of the bake shows in a capture of a moving sun. |
| Aerial perspective | The planet's air, as the sky itself is: a scene of a few hundred meters barely changes and one of kilometers fades into the horizon. Haze is `mie`. Revisit if a world built to scale reads too hazy or too clear. |
| The scene in R11G11B10F | Measured, not taken: 0.17 ms of a frame, from resolve, reflections and blending, for rings round the sun in the sky's gradient at the sea view, which six bits of mantissa cannot hide, and the outlines through walls lose the alpha they mask by. RGBA16F stays. Revisit with a dither before the scene is written, if a frame comes that close. |
| The fog's froxels | 96 by 54 by 48 (`FogSettings`), a quarter of the froxels it had, for about half the cost: the B-spline read hides the coarser squares, and the bench's views read the same. One trilinear read in place of the B-spline's four saves 0.03 ms and shows the squares; not taken. Revisit if a project's shafts need to be sharper than a lamp's width. |
| Fog read B-spline filtered across the screen | Adopted: read trilinear alone, a small glow in fog showed every froxel's square. Four trilinear reads weighted as a cubic B-spline (`shaders/opengl/include/bspline.glsl`) hide them; a glow one froxel wide comes out broader and dimmer at its peak. Revisit if the reads' cost shows in a capture of the passes that fog. |
| Lighting a particle once, not at each corner | Declined: measured no faster. Revisit if a profile shows the particle pass's vertex work. |
| Particles simulated on the GPU | Declined: the CPU steps and flattens a scene's particles in a small share of a frame, and a strike asks the physics world, which lives on the CPU. Revisit if a capture shows `ParticleSystem`'s step. |
| Sub-emitters and ribbons | *Position.* Not in the engine. An effect is emitters side by side, each its own rates and bursts, with a trail behind each particle: a child born of a parent's particles and a strip through a whole emitter were each a second way, used by one lab emitter between them. A missing feature, added when a project asks. |
| Particles after the color resolve | Adopted: they draw into the resolved scene, a sample a pixel: blended into every sample they cost more for edges they fade from anyway. The price is a hard-edged card's rim against what stands before it, stepped: a fraction of a percent of the sprites test's pixels, and none in the lab, whose particles are soft. Revisit if a project's particles are hard-edged and near the eye. |
| Smoke at half resolution | Adopted ([rendering.md](rendering.md#particles)): smoke many layers deep blended every sample of the color and the reflection inputs at full size, while a few puffs cost less at full size than a half-size target's own draws, so smoke goes to one only once it would cover the scene many times over, and back under a lower cover, a choice held a few frames, so smoke at the line does not flicker between the two. A depth-aware upsample (Bavoil's nearest-depth) keeps it off what stands in front, without a second pass at full size along silhouettes. Additive particles stay at full size, as sparks are small and bright, and so does distortion. Revisit if smoke shows blocks along an edge, or a capture shows the switch landing on the costlier side. |
| Waves of FFT swell drawn from a spectrum | Adopted (Tessendorf): every wavenumber of a few small repeating grids a wave, hundreds where a summed sea has dozens that read as regular. They are the scene's, in its environment (`Environment::waves`), and each water takes its share: a component on an entity would need a rule for which, and a spectrum per water a set of grids each, every frame. Floating stays exact and immediate: the CPU draws the same grids by the same transform, read between texels as the GPU reads them, only when something asks of it, a floating body or a query - a sea nothing floats on and nothing asks about costs the CPU nothing, and a headless server floats on the sea the clients draw. The grids' sizes are not multiples of one another, so their repeats do not line up. A Gerstner sum ran before it; a GPU readback was rejected as a frame late and absent on a server. Waterline foam is read off a world-space shore, not the screen's depth, which foamed only what the camera saw. Revisit with a cascade of finer grids if a project's water is seen at a few meters and its swell's shortest wave shows. |
| What the sea costs a frame | A scene with no water builds and draws none of it, and a frame draws each of the ripples, the swell and the shore only while it draws water that takes it ([water.md](water.md#how-it-works-inside)); turning back to it draws them all at once. Then each ripple field on its own clock, at most `GLWaveFields::FIELD_RATE` times a second: taking turns at one a frame, a field moved every third frame at 60 fps, and the sea's detail pulsed. The shore `GLWaterPass::CAPTURE_RATE` times a second: it was two draws of the scene and two transforms a frame, for a line that follows waves seconds long. The waterline foam stays: it is most of what makes the shore read as one. Revisit if a character wading shows its ring lagging. |
| One water | *Position.* Water is a `Water` on a mesh, and a sea is water with other values: a pond, a river, a pool and the sea are one component, one way of shading and one question gameplay asks (`WaterData::at`). Its `waves` is its share of the scene's swell and surges and `ripples` its share of their ripples, so the sea is water taking all of both; its `flow` runs along its mesh's UVs, so a river is a strip - no spline or flow-map tool; its `depth` says where it ends below, none for the open sea; and it foams at its crests and waterlines by its own `foam` and `waterline`. Its material holds its optics alone, so nothing about the material says it is water: a second statement of that could disagree. Water draws with programs of its own. Waterline foam is captured at one level a frame, the nearest foaming water's. Revisit for a lake large enough to raise its own waves, or waterlines at two levels in one view. |
| Reflection inputs written only for glossy runs | Measured, not built. Masking both targets for every opaque run, the most it could buy, saved under 0.1 ms of Forward, with nothing traced at all; which runs could be masked is not known ahead, as a roughness map can take any material under the limit. Revisit if a capture shows those writes. |
| What the forward shader's parts cost | Measured by A/B of shader variants, one thing out at a time, at one locked GPU clock, before the soft filter went ("Every live shadow by the hard filter"). Direct light was the largest part in every view, most of it the live shadows; the environment, a layered material's layers and fog came next, and a constant color - what vertices, raster and blending cost - was about a sixth of the whole. The shader is bound by its size as well as by what runs: the soft filter's code, left in a path no pixel took, cost its share all the same. When last measured, the rest were each inside the noise, so stay as they are: one fog read in place of four (and it shows squares), the global IBL skipped under a full probe, the sky's lightmap, GTAO's read, the volume, normal maps, specular AA, the optional features, the reflection inputs' writes, fades, and `early_fragment_tests`, which already happens. A receiver plane's matrix is not the cost: with the slope off a filter takes longer, so a matrix in the UBO is not built. Revisit each if a capture on a scene of its own shows it. |
| Shader permutations | A fixed set, adopted, and no general permutation system: the forward program is compiled with `PLAIN`, `LAYERED`, `SKINNED` and `BAKED` in the combinations `GLForwardPrograms` builds. Layered and skinned are what a draw needs - its surface blended from layers, its vertices posed. Plain and baked are cost. Plain (`GLMaterial::plain`) compiles out the optional features for a material that uses none, as they cost even where unused. Water is another kind of surface, so a program of its own (`shaders/opengl/scene/forward/water`, `shaders/opengl/scene/forward/prepass/water`) built from the same modules, not a variant: in the lit programs its varyings alone were 0.05 ms at spawn. Baked (the programs under `BAKED`) compiles the lightmap read, and the per-light branch on it inside the light loop, into the programs of opaque static runs alone: as a uniform branch they would sit in every draw that never reads a lightmap - glass, posed meshes, the captures. Revisit for another such variant when a feature's cost shows on draws that do not use it. |
| Anisotropic and parallax lobes | *Position.* Not in the engine. Each ran in the shader's light loop or at the top of every fragment for a look few surfaces want, and a parallax march is a stretched texture at any grazing angle. Sheen, clearcoat, transmission and subsurface stay. A missing feature, added when a project asks. |
| Hoisting the shadow pass's sort | Built, measured, reverted: sorting the casters once cost what sorting each tile's indices saved. Revisit if a caster shrinks to an index. |
| Buffer-stall fixes | Built, measured, reverted: the shadow instances' upload was not a stall. The persistently mapped ring (the GL floor below) did win, by removing the driver's copy. Revisit if an upload shows as a stall in a capture. |
| Keeping a batch's order while its keys hold | Adopted: a batch keyed as the last one was, key for key, keeps the order it was sorted into rather than sorting again (`GLInstanceBatcher::buildGrouped`), so a still view, or one where what moves keeps its draw, sorts nothing. The keys are still built every frame: knowing which changed would take a record per object the batch does not keep. Revisit if building the keys shows in a capture. |
| A radix sort of the batch keys | Built, measured, reverted: the batch's cost is building the keys, not sorting them. Revisit if the sort itself shows in a capture. |
| Hashing shadow signatures a word at a time | Adopted (`fnv1a64Words`): with hundreds of moving casters the byte-wise FNV-1a of each one's matrix was most of the workers' cull, and the frame waited for it before the shadow pass. A tile's signature is compared only with its own, so it need not be the byte-wise hash. Revisit if the cull shows in a capture again. |
| `KHR_parallel_shader_compile` | Adopted: the backend's programs are linked on the driver's own threads and asked whether they are done (`ShaderBase::compileInParallel`), so a cold start shows the splash, not a held window ([rendering.md](rendering.md#bakes)). On two of the driver's threads, not all it offers: with more, the driver measured corrupted the heap on a start that found some programs in its disk cache and built several anew - a game's first start after an update - nearly every time at its maximum, and in none of 46 at two, for half a second more on a start with nothing cached. A driver may still build a program on the calling thread, as its link status is asked; the checks are spread over frames, a share each, and stop at the first slow one while the splash shows, so it holds at most one program's build. Revisit with shared contexts on worker threads if one program's build shows as a hitch in the splash, and the thread count on another driver. |
| A no-error context (`KHR_no_error`) | Built, measured, reverted: no change on the driver measured. Revisit on another vendor's driver. |
| The driver's threaded optimizations (`__GL_THREADED_OPTIMIZATIONS`) | Measured, not taken: set for the shipping game and timed by turns with it unset, at a window small enough for the CPU to bind, the mean frame held or fell a little while the slowest 1% of frames grew in every view, and a frame must be steady. Revisit on another driver, or a CPU with cores to spare beside the pool's. |
| A subgroup-scalarized light loop | Built, measured, reverted: the forward loop taking each wave's lights one shared index at a time (`ARB_shader_ballot`) was slower where measured. It is made for a GPU with a scalar unit (Drobot, SIGGRAPH 2017); revisit on one, keeping it only if the others do not lose. |
| Bindless textures | Not built. llvmpipe, which CI renders on, has no `ARB_bindless_texture`, so the bound-texture path would stay beside it forever. Materials in one buffer with draw IDs waits on it. Revisit with the Vulkan backend, where descriptor indexing is core. |
| The sun's cascades culled on the GPU | Declined. The shadow cull already runs on the workers; what the render thread keeps - the casters' keys and upload signatures - is needed whoever culls, and a GPU cull would lose the shadow-tile cache's skip of an unchanged tile. Revisit if the workers' shadow cull shows in a capture. |
| Multi-draw indirect | Adopted. Every mesh lives in one `GLMeshPool`, so a run of different meshes goes out as one `glMultiDrawElementsIndirect` per change of program, winding, material or vertex layout, cutting the shadow and depth passes' CPU with GPU time unchanged. Revisit if building the commands shows in a capture. |
| Link-time optimization of the shipping engine | Measured, not taken: GCC's LTO over the runtime and the engine's libraries, timed by turns with the shipping game at a window where the CPU binds, moved no view past the noise, and inlined miniaudio across files into two new warnings. Revisit if the engine becomes one library, or a profile shows calls across its files. |

| A gameplay module's precompiled header | Adopted: `vkm_gameplay_module_options` precompiles `system/script/behavior_api.h` for every module, and the build sets the module's log category (`GAME`), as a file's own define would redefine the precompiled one. | A changed behavior running within 3 s | Reached with Clang, not with GCC. The editor reloads the moment a build stamps `game.built` (`ReloadWatcher`), and a reflect block builds its field tuple in one step (`fieldTuple`, `base/reflect/reflect.h`): a one-file lab change runs again in play about 2 s after the save with Clang, over 6 s with GCC. The rest is GCC's build: each file pays about 2.7 s on the precompiled header, as GCC instantiates again the templates its headers' inline code uses, its own code 1.6 s more at -O2 with debug info, and the link 0.7 s. A development module at -O0 was measured and not taken: without debug info a one-file change still rebuilds past 3 s, and a debugger no longer sees a behavior's code; with debug info it keeps the debugger and saves less. Its frame cost is one development could carry, but neither reaches the target, as the header's instantiation is most of a file's time at any optimization. What would reach it: a gameplay header whose inline code instantiates little. Revisit with a GCC that keeps a header's instantiations, or if a slower development frame is worth -O0's 3-4 s on the larger files. |

Spots and point lights keep every caster in one map, as they are held whole while nothing in them moves and draw little when they are not. Revisit if a project's spots draw enough for their fixed casters to show. |
| Live shadow maps of fixed lights drawing only what moves | Built for the sun, not from the bake: the baked maps are coarser than the near cascades, 4 to 25 times, so a baked source would blur the shadow at the camera. The held layers are drawn live at their own density instead, and kept. A lit texel of a fixed mesh still reads both maps: it reading the tile alone was built, saved a little in every view, and dropped: a fixed caster changed in play then cast nothing on a baked floor until a bake took it in. The other fixed lights' live maps hold every caster, as above. Revisit with a scene whose fixed spots' or point lights' redraws dominate a capture. |
| Area lights | *Position.* Not in the engine. A wide spot or a row of them lights what a panel would, with the shadows an area light could not cast, and each area light took a branch in every loop that reads a light. A missing feature, added when a project asks. |
| Authenticating or encrypting packets | Declined. The join token stops floods and spoofed joins, but an on-path attacker can still read and forge a session. Closing that needs a key exchange - connect tokens issued by a backend (Fiedler), or DTLS - and a LAN game or a self-hosted server has no backend. Trigger: internet play through a matchmaker that can issue tokens - and it is required before a game is played with strangers over the internet. |
| clang-format and clang-tidy for the mechanical rules | Not adopted. The `docs` suite holds the tree to its rules, including ones a formatter would need fencing off from, and runs with the build with no extra tool. Trigger: a semantic rule (linkage, `override`) the suite cannot express and review keeps catching by hand. |
| A log line a second | Removed: the FPS line wrote to the log from the frame, and a write blocks while the disk flushes, for tens of milliseconds on a busy disk; the bench's worst frames fell on that line's ticks. The rate shows on screen (`showFrameRate`). A shipped game logs nothing per second; a development build keeps the net line. Revisit if a game needs a log line in steady play, which then needs a writer off the frame's thread. |
| A shipping build of the engine | *Position.* A game ships on `VKM_SHIPPING` - `Release`, asserts, the profiler and debug drawing off, debug info kept for reading a crash - and its module is built again against it; the editor and every other command run the development engine, asserts on. A player's game has no use for an assert's stop, a profiler's thread and listening port, or a developer's debug lines ([building.md](building.md#the-shipping-engine)). |

Any obvious render idea has probably been tried: read [rendering.md](rendering.md)
before proposing one, and measure before and after.
