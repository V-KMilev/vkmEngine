# vkmEngine - Full Source Audit

**Date:** 2026-05-30  
**Scope:** every tracked source file under `src/` (~230 files across editor, engine systems, OpenGL backend, tools, app).  
**Method:** 30 parallel reviewer agents (one per coherent file group, each reading its files in full) + 1 synthesis pass, audited through four lenses - **over-specification** (concrete code that should be generic), **refactor/update**, **cleanup/simplify**, **missing features** (editor-weighted) - and cross-checked against [code_style_guide.md](docs/misc/code_style_guide.md).  
**Total findings:** 249

Categories: **Over-specified** (concrete-where-should-be-generic, or the inverse: single-user speculative abstraction) - **Missing Feature** - **Refactor** - **Cleanup / Simplify** - **Style Violation**. Severity: High / Medium / Low. Confidence: reviewer's certainty the finding is real.

---

## 1. Executive summary

vkmEngine is in fundamentally good architectural health. The core layers - ECS (type-erased Scene over SparseSet<T>), ResourceManager (generic versioned registry with no per-type switches), the render graph (type-erased resource registry with debug access-drift checking), and the platform/threading primitives - are genuinely well-designed, well-documented, and fit the engine's grain. Reviewers repeatedly noted that several "generic mechanisms" (g_textureMappings, AssetFactories, LIGHT_TYPE_NAMES, the data-driven RenderMode picker, the reflection-driven component serializer) are exemplary and earned their complexity. Correctness defects are few but real: the standout is AssetId::toString truncating every GUID to its low 32 bits on the project's LLP64 (MinGW-UCRT64/MSVC) toolchain, which silently corrupts the asset-identity system the whole serialization path depends on. Two other High-severity correctness issues - the runtime-settings overlay writing to a per-frame mirror that is overwritten every frame, and OcclusionOracle::invalidate() being documented as the scene-swap guard but never called - are both verified and have clear fixes.

The dominant systemic themes are exactly the three the user prioritized. (1) Over-specification by duplicated scaffolding is pervasive in the backend: the same backend-type-guard + GLBackend downcast is copy-pasted into all 19 GL passes, the render-to-PostScratch-then-blit-back dance is reimplemented across four post-FX passes, five GL resource wrappers hand-roll identical UBO/lifecycle code, and two mip-chain targets (GLBloom/GLHiZ) are near-duplicates. (2) The editor has a coherent cluster of missing features centered on an incomplete undo story (inspector field edits, hierarchy context-menu mutations, asset-browser edits, and model import all bypass the existing command stack) and read-only asset management (no rename/delete despite the backing APIs existing). (3) Speculative abstraction appears in several places where a generic mechanism serves exactly one (or zero) consumers - the EventSystem pub/sub framework with zero subscribers being the clearest. Style drift is real but low-severity and concentrated: banned /*name*/ unused-param hybrids, include-ordering slips, missing override keywords, and inconsistent namespace-close comments. None of the architecture is on a bad trajectory; the work is consolidation and finishing half-built features, not redesign.

## 3. Cross-cutting themes

Patterns that recur across multiple areas (from the synthesis pass).

| # | Theme | Severity | Description | Affected areas |

| 1 | **Duplicated GL backend scaffolding that wants a shared GLRenderPass base** | High | Every one of the 19 GL passes opens execute() with an identical backend-type guard + LOG_ERROR + static_cast&lt;GLBackend&amp;&gt; block (verified: 19 files), and each constructs its own ScreenTriangle despite the type's own doc promising 'one shared instance covers all passes'. A thin GLRenderPass : public RenderPass intermediate could perform the guard+cast once, hand subclasses a typed GLBackend&amp;, and own the shared screen triangle - removing ~3 boilerplate lines and one failure mode from every pass. ## 4. Top prioritized actions

Ranked by impact-vs-effort (from the synthesis pass).

| Rank | Action | Rationale |
|---:|---|---|
| 1 | **Fix AssetId::toString LLP64 truncation (%016lx on unsigned long)** | Verified High-severity correctness bug. On the documented MinGW-UCRT64/MSVC toolchain unsigned long is 32-bit, so every GUID serializes as only its low 32 bits; two distinct AssetIds can round-trip to the same value, silently corrupting the asset-identity system the entire AssetDatabase/findById/serialization path depends on. One-line fix (use %016llx with unsigned long long, or PRIx64). Maximum impact, near-zero effort, and it underpins the data-loss material-duplication bug too. |
| 2 | **Close the editor undo gap: route inspector/hierarchy/asset edits through the command stack** | The single largest user-facing quality gap, flagged by five reviewers. The command machinery (including TransformChangeCommand::tryMerge built for inspector micro-edits) already exists; the work is wiring inspector scalar edits, hierarchy context-menu mutations, asset-browser edits, and model import to push commands instead of only markSceneDirty(). High impact on user trust, moderate effort, no new abstractions needed. Fold in adding ReflectionProbe to EntitySnapshot as part of the same pass. |
| 3 | **Add ReflectionProbe to EntitySnapshot and sync the extern-template list** | Verified High-severity data-loss bug: destroy+undo on an entity with a ReflectionProbe silently drops the probe, despite the snapshot doc explicitly saying new component types belong there. Small, localized edit (add the optional&lt;ReflectionProbe&gt; field + capture/apply + extern-template line). High value, trivial effort. Natural companion to priority 2. |
| 4 | **Fix runtime-settings overlay writing to the overwritten m_environment mirror** | Verified High-severity correctness bug: render_system.cpp line 74 overwrites m_environment from the scene EnvironmentConfig every frame, so bloom/exposure/shadow/transparency slider drags in the overlay revert instantly. The viewport toolbar already demonstrates the correct pattern (write to the scene component). Low effort, fixes a feature that currently silently does nothing. |
| 5 | **Introduce a GLRenderPass base to eliminate the 19x guard+downcast duplication** | Verified: the identical backend-type guard + static_cast&lt;GLBackend&amp;&gt; is copy-pasted into all 19 GL passes. A thin GLRenderPass : public RenderPass that performs the guard+cast once, hands subclasses a typed GLBackend&amp;, and owns the shared ScreenTriangle removes ~3 boilerplate lines and one failure mode from every pass. Highest-leverage over-specification cleanup - directly addresses the user's primary lens and touches the most files per unit of design effort. |
| 6 | **Extract the post-FX render-to-scratch / blit-back helper** | DoF/MotionBlur/LensFlare/SSR/TAA reimplement the identical in-place fullscreen-transform-of-HDR sequence. A single helper (taking the per-pass uniform-binding closure) collapses five copies and makes new post passes trivial. Medium effort, high consolidation value, and pairs naturally with the GLRenderPass base in priority 5. Compute camera-reprojection velocity (prevViewProj/havePrev) once per frame while here to de-duplicate TAA/MotionBlur history. |
| 7 | **Make the keybind vocabulary a single data-driven table** | The 20 keybinds are hand-enumerated in ~5 disconnected places with no compile-time link; a missed entry silently drops persistence/conflict-detection/dispatch. Replacing with one {jsonKey, label, member-pointer} table that load/save/preferences/dispatch all iterate eliminates a whole class of silent bugs and lets Frame All and New Scene join the generic mechanism. Medium effort, removes recurring maintenance hazard called out by four reviewers. |
| 8 | **Call OcclusionOracle::invalidate() on scene swap (and add the missing camera-teleport hook)** | Verified High-severity correctness gap: invalidate() is documented in two headers as the scene-swap/teleport guard but has zero callers, so after a scene swap the new scene's AABBs are culled against the old scene's stale viewProj/pyramid, wrongly culling visible geometry. Small fix (wire it into onSceneChange / scene-load), high correctness payoff. |
| 9 | **Surface asset rename/delete in the Asset Browser using existing APIs** | The browser's whole job is asset management yet offers no rename or delete, while ResourceManager::rename exists and MaterialPreviewSession::evict is dead code specifically written for the delete path. Closing this (plus the Environment search-by-effect-name and the New Scene command) addresses the editor missing-feature cluster with mostly-existing plumbing. Medium effort, clear user value. |
| 10 | **Prune speculative/dead abstractions and run a style-compliance sweep** | Low-risk, high-tidiness consolidation: inline-or-remove the zero-subscriber EventSystem, the no-caller RenderPassFactory methods, the one-user backend-work hook, dead getters (FrameLimiter, taskCount), the dead gl_common.h/components.h/keyframe.h aggregate headers, and the unused widgets. Combine with a mechanical style pass (banned /*name*/ hybrids, missing override on GLFramebufferTarget::getColorTexture, transitive-include fixes, namespace-close comments, k-prefix/PascalCase constants). Each item is small; batched, they remove real maintenance drag and bring style enforcement back to uniform. |

## 7. Completeness notes

The per-area passes were structured by directory and almost certainly under-covered cross-area interactions and whole-system properties: (1) No reviewer assessed test coverage - I saw zero mention of unit/integration tests anywhere, which for an engine with this much serialization/undo/threading complexity is itself a likely gap worth confirming. (2) The serialization round-trip was reviewed file-by-file but no one traced a full save->reload of a non-trivial scene end-to-end; the AssetId truncation, material-duplicate-collapse, and RenderMode-as-int issues are all serialization-correctness bugs that only fully manifest across the boundary between areas, suggesting more may lurk. (3) Threading hazards were caught locally (setVSync stealing the GL context, stb_image's global flip flag, OcclusionOracle staleness) but no one did a holistic main-thread-vs-render-thread ownership audit of which APIs are safe to call from the editor/main thread once RenderThread owns the GL context - the setVSync bug implies others may exist (any editor control that touches the backend). (4) Performance was assessed per-file (per-frame vector<bool> allocations, glReadPixels stall, recomputeDerived re-sort) but there is no end-to-end frame-cost or GPU-stall picture. (5) Shaders/GLSL were entirely out of scope - the reviews covered C++ that loads and binds shaders but not the shader programs themselves, their variant explosion, or uniform-interface drift (several findings hint uniform presence is fragile). (6) Build system, CMake GLOB behavior, and the submodule (vkmGL/modules) were not reviewed despite the git status showing modules/vkmGL is modified. (7) Memory-safety beyond the noted fixed-buffer strcpy/snprintf juggling (status bar, icons, keybind labels, probe HDR path) was not systematically audited; those C-string patterns recur and a focused pass might find an actual overflow. (8) The .codeboarding/ directory and the new scenes/*.json files in git status were not examined and may be relevant artifacts. Finally, the relative severity calibration across 30 independent reviewers is uneven - 'High' in the editor (a missing undo) is not the same risk class as 'High' in resource (silent GUID corruption); I re-ranked the top priorities on absolute impact rather than trusting per-area severity labels uniformly.
